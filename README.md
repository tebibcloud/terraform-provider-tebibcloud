# terraform-provider-tebibcloud

The TebibCloud provider for Terraform and OpenTofu (Phase 7, ADR 0042). It manages resources
through the public API (`/api/v1` on `console.tebibcloud.com`) with the same credentials as the
`tebib` CLI.

Moving from `tebibhost/tebib` 0.1.0? See the 0.1.0 entry in CHANGELOG.md.

Preview (0.x): breaking changes are allowed before 1.0.0 and are listed in CHANGELOG.md.
It is on the [Terraform registry](https://registry.terraform.io/providers/tebibcloud/tebibcloud/latest).
It is not on the OpenTofu registry yet; until it is, OpenTofu installs it with
`source = "registry.terraform.io/tebibcloud/tebibcloud"`.

This directory is developed in the TebibCloud platform monorepo and copied to the public
[tebibcloud/terraform-provider-tebibcloud](https://github.com/tebibcloud/terraform-provider-tebibcloud)
repository at each release: change it in the monorepo, not in the public repository.

## Use

```hcl
terraform {
  required_providers {
    tebibcloud = { source = "tebibcloud/tebibcloud" }
  }
}

provider "tebibcloud" {}   # settings from TEBIB_* or your `tebib configure` profile
```

Settings, first match wins: the provider block, then `TEBIB_ENDPOINT`, `TEBIB_ACCESS_KEY_ID`,
`TEBIB_SECRET_ACCESS_KEY`, `TEBIB_ORGANIZATION`, `TEBIB_PROJECT`, `TEBIB_PROFILE`, then the CLI
profile files in `~/.config/tebib`, then the defaults. A full example (VPC, NAT gateway, VM,
volume, public IP, SSH key) is in [examples/complete](examples/complete/main.tf). The resource
docs are in [docs/](docs/), generated by `go generate`.

## How it works

- Auth: `Authorization: Bearer <key id>.<secret>`, as the CLI does. Role sessions (`TBS...`)
  work too.
- Asynchronous changes: the API answers 202 with `creating`, `updating` or `deleting`. The
  provider polls until the resource is `active` (or gone), within the `timeouts` block.
  A resource that ends in `error` stays in the state as tainted, so the next apply replaces it.
- Creates the API de-duplicates (project resources) send an `Idempotency-Key` and are retried
  on 502/503/504. IAM creates are sent once. Any call is retried on 429.
- Drift: every read refreshes from the API. Something deleted outside Terraform is removed
  from the state and made again.
- Known limits: the API never returns a VM's `user_data`, so it isn't refreshed. An access
  key's secret is only known when it is created, and it is stored in the state.

## Develop

Needs Go (see `go.mod`) and `terraform` or `tofu`.

```sh
go test ./...                 # unit tests: Terraform/OpenTofu against the fake API (internal/mockapi)
go generate ./...             # regenerate docs/ from the schema and examples/
go build -o ~/bin/terraform-provider-tebibcloud .
```

To try a local build, point a CLI config at it (`TF_CLI_CONFIG_FILE`):

```hcl
provider_installation {
  dev_overrides { "tebibcloud/tebibcloud" = "/home/you/bin" }
  direct {}
}
```

Acceptance tests use a real endpoint and create billed resources:

```sh
TF_ACC=1 TEBIB_ACCESS_KEY_ID=... TEBIB_SECRET_ACCESS_KEY=... TEBIB_ORGANIZATION=o-... \
  TEBIB_PROJECT=p-... go test ./internal/provider -run TestAcc -timeout 60m
```

## Release

1. Run the acceptance tests against the lab (above) with a test project.
2. In CHANGELOG.md, turn `## X.Y.Z (unreleased)` into `## X.Y.Z (YYYY-MM-DD)`.
3. Tag the monorepo `terraform-provider-tebibcloud-vX.Y.Z` and push the tag.

The monorepo's `.github/workflows/terraform-provider-release.yml` then copies this directory
(`git subtree split`) to the public repository's `main` and tags it `vX.Y.Z`. There,
[.github/workflows/release.yml](.github/workflows/release.yml) builds the release with
goreleaser: zips per platform, `SHA256SUMS`, its GPG signature (the registries require it) and
a keyless cosign signature, and publishes it. registry.terraform.io picks it up from the
GitHub release (the OpenTofu registry will too, once the provider is listed there). A dry run of the build (no signing, no push) is the
monorepo workflow's manual run.

The release key: RSA 4096, `TebibCloud Releases <releases@tebibcloud.com>`, fingerprint
`83C01CCF0547A9F4EC2EDBB2EB23A14F9FBCD168`, expires 2028-11-06. Its private part is only in
the public repository's `GPG_PRIVATE_KEY` secret and an offline backup.
